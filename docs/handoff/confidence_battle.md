## Method

For each row: read the decompilation (`analysis/decomp/battle/<addr>_*.c`, overlays in
`analysis/decomp/battle_ovl/`) or the disassembly (REA CLI: `scratchpad/fx_worker/cat3/asm.py ELF
ADDR`, ELFs `analysis/elf/SO2_boot+prog2129.elf`, `scratchpad/battle/modules/char01_live.elf`
for #1984.0 / #1984.1 / #1981 at run time; `v.py MODULE ADDR` names the jal targets; `twin.py
MODULE ADDR:END` finds same-code twins) and compare with the port column's C++.
- Matches in full, or exercised by a passing Redux reference that the port reproduces
  (`tools/refs/refs.csv`, `scratchpad/regress/full_resync_pass/summary.md`): `confirmed`, with
  the evidence.
- Name / summary wrong: corrected (`snake_case subsystem_verb_object`; SDK names kept).
- Port behaviour differs: not rewritten; listed under "Port leads" below.
- Can't settle: confidence left, reason in the evidence.
- The 51 battle "functions" past #2129's live code (0x800715d0-0x80088054) that REA split at
  #1984 / #1981 entry points are overlay entry points (effects phase 8); keep that framing.

Helper: `scratchpad/conf_battle/show.py MODULE ADDR` prints the row, the decomp dump and the
engine lines citing the address. Work list: `scratchpad/conf_battle/todo.csv` (the 239 rows at
the start, with sizes).
